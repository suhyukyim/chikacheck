# 여기서 시작 (치카체크 웹 키트)

## 1. 이 폴더에 있는 것
| 파일 | 내용 |
|---|---|
| `CLAUDE.md` | Claude Code가 매번 자동으로 읽는 코딩 규칙 |
| `docs/PRD.md` | 무엇을 만드는지: 기능, 계산 규칙, 데이터 구조 |
| `docs/DESIGN.md` | 어떻게 보이는지: 제안서 2-2 시안 기준 색·레이아웃·문구 |
| `docs/PIPELINE.md` | 어떤 순서로 만드는지: Stage 0~9 + 완료 기준 (명령어 원본) |
| `.claude/commands/` | VSCode Claude Code 채팅창에서 쓰는 `/stage-1`~`/stage-9`, `/check`, `/fix` |

## 2. 순서
1. `docs/PIPELINE.md`의 **Stage 0** 대로 준비 (Live Server 설치, GitHub 저장소, 첫 커밋)
2. 이 폴더를 VSCode로 열고 Claude Code 채팅창에 `/stage-1`
3. 보고서의 완료 기준 확인 → 직접 눌러보기 → 커밋 → `/clear` → `/stage-2` …
4. 막히면 `/fix 증상`, 넘어가도 되는지 애매하면 `/check 번호`
5. Stage 9에서 GitHub Pages 배포 + 발표 리허설

## 3. 시간 감 (대략)
| Stage | 내용 | 예상 |
|---|---|---|
| 0 | 준비 | 15분 |
| 1~2 | 뼈대, 계산 로직·테스트 | 1시간 |
| 3~4 | 타이머, 가상 본체 | 1~1.5시간 |
| 5~6 | 내 친구, 부모 화면 | 1~1.5시간 |
| 7~8 | 시연 도구, 다듬기 | 1시간 |
| 9 | 배포, 리허설 | 30분 |

## 4. 발표 전에 꼭
- 발표가 낮(12~17시)이면 설정 → **발표 모드 시간대 고정: 저녁** (안 하면 시연 기록이 달력에 안 나옴)
- 설정 → **데모 데이터 채우기** + **배속 ×10** → 3분 양치가 18초에 끝남
